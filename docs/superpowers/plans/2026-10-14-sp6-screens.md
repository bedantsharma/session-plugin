# Sub-project 6: Screens — Implementation Plan

> **For agentic workers:** Execute task-by-task, test-first. Steps use checkbox (`- [ ]`) syntax. This plan gives interfaces, behaviour rules (pseudocode) and test cases — no full code. Read the cited spec sections and the existing code (sub-projects 1–5) first and follow its patterns: events → projector → views (`Store::write`, `append_in`, `VIEW_TABLES`), owner events with `session_id = owner` (`OWNER_SESSION`, `owner_action`), the never-fail hooks, MCP tools with `Args<T>` in `src/mcp.rs`, and the text `status` in `src/status.rs`. Add every dependency with `cargo add <crate>@<ver>` / `npm install` (exact current versions; check they support Svelte 5 / Tailwind 4 / Vite 8) — never hand-edit manifests.

**Goal:** The owner sees everything at a glance and can act from it, on three screens: the terminal (`bridge-screen status` and a live `bridge-screen watch`), a local browser dashboard (`bridge-screen ui`), and an inline card in the Claude desktop app (`show_progress`). Plus opt-in progress reports for publishing (`progress_report`). All three screens show the same facts from one model and record owner clicks as the same events the CLI records.

**Architecture:** A new core module `view` builds a serialisable **glance model** (projects, needs-you queue, live sessions) and the drill-down models (project, session, task, history, tuning) from the views — read-only, with `now` passed in. A new core module `owner` holds every owner action (drift answer, label, leftover resolution, verify ✓/✗, tuning revert) so the CLI, dashboard, `watch` and the desktop card all call the same function and record the same `owner_action`. `status` is re-rendered from the glance model (text unchanged). The binary gains: `ui` (axum on `127.0.0.1`, token, single instance, JSON API, embedded SPA), `watch` (ratatui), and MCP `show_progress` (MCP Apps card + text fallback), `owner_action` (card-only), `progress_report`, `report_published`. The Svelte app (Svelte 5 + Tailwind 4 + shadcn-svelte + LayerChart) has two Vite entries: the dashboard and a single-file card bundle.

**Tech Stack:** Rust: `axum`, `tokio` (add `net`, `rt-multi-thread`, `signal` features), `rust-embed`, `ratatui` + `crossterm`, `getrandom` (token), `tower` (dev: `ServiceExt::oneshot` for API tests, no sockets). Web: shadcn-svelte (CLI, components copied into `web/src/lib/components/ui`), LayerChart, `vite-plugin-singlefile` (card bundle), Vitest + `@testing-library/svelte` (component tests), Playwright (one e2e smoke test).

**Spec:** `docs/superpowers/specs/2026-10-13-bridge-screen-design.md` — §4.1 (`ui` single instance), §4.3 (frontend, 500 ms polling, two bundles), §5.6 (done%, claimed%, scope line, uphill de-emphasis, stuck flag), §6.3 (reads never block writers), §6.4 (127.0.0.1 only, random token in the URL), §7.6 (tuning drill-down with one-click revert), §10.1–10.6 (glance, drill-downs, terminal, theme, desktop card, published reports), §11.2 (`show_progress`, `progress_report`), §14 (dashboard API tests, component tests, one Playwright smoke test).

## Global Constraints

- Everything from sub-projects 1–5 still applies: clippy pedantic `-D warnings`, no `unsafe`/`set_var`, never-fail fast hooks (no hook changes are expected in this sub-project — if one is needed, its latency test must still pass), tests never touch the real `~/.claude`/`~/.bridge-screen` or run the real `claude`, test git calls use the scrubbed helpers (`common::git_cmd`), commit per task ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, never `--no-verify`.
- **Local only.** The dashboard binds `127.0.0.1` only (never `0.0.0.0`), on the port from `config.toml` `ui_port` (default `0` = any free port). No outbound network calls anywhere in this sub-project. Nothing is written inside a repo.
- **Token.** 32 random bytes (hex) per `ui` start, stored in `~/.bridge-screen/ui.lock` (`{pid, port, token}`, file mode 0600). The printed URL is `http://127.0.0.1:<port>/#token=<hex>`; the SPA reads it from the fragment (never sent to servers, never logged), keeps it in `sessionStorage`, and sends `Authorization: Bearer <token>` on every API call. Static assets need no token; every `/api/*` route does (401 without/with a wrong token, constant-time compare). Requests whose `Host` isn't `127.0.0.1:<port>` or `localhost:<port>` get 403 (DNS-rebinding guard). No CORS headers.
- **Reads never block writers** (spec §6.3): each API request opens its own read connection (or uses a pooled read-only one); WAL; no long transactions. Owner actions open a write via the normal `Store::write` path.
- **One model, three screens.** `status`, the API, `watch` and the card all render `view::glance(...)`. Screens contain no business rules (ordering, escalation, labels, colours by state) — those live in `view`.
- **Projectors use event timestamps only;** `now` is a parameter of the read-side model builders (live away time, crash display) and is never written into views.
- **Theme (spec §10.4):** clay `#D97757` only for progress, owner-check items and the ✱ mark; green on task, amber detour/waiting/uphill, red needs you; neutral greys otherwise; monospace for session ids, branches and file names; dark by default, light follows `prefers-color-scheme`. Reuse the tokens already in `web/src/app.css`.
- **Escalation:** more than 4 needs-you items → the count pill pulses until ≤ 4, the queue shows the 4 most urgent with "show all N", and `status` / `/bridge-screen` put the count on the first line.
- Every owner action is an `owner_action` event (plus whatever events the action itself appends), with `session_id = owner`; a click on an item that is no longer open returns "already resolved / no longer needed" and records nothing.

## Review Focus

1. **Untrusted requests to the dashboard:** a request without the token, with a wrong token, with a foreign `Host` header (DNS rebinding), or a cross-site form POST must be refused (401/403) and record nothing. Test: `api_rejects_untrusted_requests` (Task 3).
2. **Single instance and stale locks:** a second `bridge-screen ui` prints the running instance's URL and exits 0; a `ui.lock` left by a dead process (pid not running, or port not answering) is replaced, not obeyed. Test: `ui_lock_single_instance_and_stale` (Task 3).
3. **Stale or double clicks:** acting on a needs-you item that was already handled (CLI in another terminal, a second browser tab, a double click) answers "already resolved" and appends nothing. Test: `stale_owner_action_records_nothing` (Task 2).
4. **Status text unchanged by the refactor:** every existing `status` test passes unmodified after `status` renders from the glance model, plus a new golden covering every needs-you kind and the escalation line. Test: `status_from_glance_matches_every_kind` (Task 1).
5. **Missing web build:** `cargo build` / `cargo install` without `web/dist` still compiles, and `ui` then serves one page that says how to build the dashboard (`npm --prefix web ci && npm --prefix web run build`), while `/api/*` keeps working. Test: `ui_without_built_assets` (Task 3).

### Task 1: The glance model and `status` from it

**Core `view` (all `pub`, all `Serialize`, `now: jiff::Timestamp` passed in):**
```
glance(conn, cfg, now) -> Glance {
  live_sessions: usize, projects: Vec<ProjectRow>, needs_you: Vec<NeedsYou>, escalated: bool (needs_you.len() > 4)
}
ProjectRow { repo_id, name, goal: Option<{id, title}>, done_pct, claimed_pct, unestimated,
             milestones: Vec<{id, title, hill, done_pct, stuck}>,   # §5.6 uphill + stuck flag
             leftovers: {open, report_only}, tuned: Option<String>, forecast: None, sessions: Vec<SessionRow> }
SessionRow { session_id, short, state_label (working|idle|needs you|ended), light (green|amber|red),
             task: Option<{id, title}>, detour: Option<{label, reason}>, units, active_min, nav_text,
             flags: [checkpoint_pending|checkpoint_missed|readback_pending|verify_pending(ids)], branch, worktree }
NeedsYou { id (stable: kind + target), kind, repo_id, session_id?, title, detail, actions: Vec<ActionSpec>, rank }
  kinds and actions (spec §10.1):
    drift_red        → Continue | Make it a task (needs parent+title) | Stop
    checkpoint_missed / handoff_unstable → (info, no buttons; detail says what the agent owes)
    permission_wait / idle_wait          → (info)
    verify_overdue   → ✓ Works | ✗ Broken (note)
    leftover (owner-decidable)           → Adopt | Resume | Undo   (one item per dead session, listing its files)
    squash_failed    → (info)
  rank = today's status order: red, missed checkpoint/unstable, waits, verify overdue, leftovers, squash
```
- Stuck flag (§5.6): a milestone whose hill state and done% haven't changed across the last 3 sessions that worked on tasks under it. Compute from `units.task_id` → milestone, and the plan/verification events between those sessions' start times. Pure read.
- Move the ordering/label/light rules out of `src/status.rs` into `view`; `status::render` becomes a text renderer of `Glance` (plus the dashboard URL line when `ui.lock` names a live instance, and `N need you` first line when escalated).

### Task 2: Owner actions in one place

**Core `owner`:**
```
enum OwnerAction {
  Drift { session, answer: continue|make_task|stop, parent?, title?, estimate? },
  Label { session, unit_no, label },
  Resolve { leftover_ids, action: adopt|resume|undo },
  Verify { repo, task, level (default 4) }, Broken { repo, task, note },
  ResetDrift { repo },
}
act(store, home_paths, cfg, action, now) -> Result<String /* reply line */>
```
- Move the bodies of the CLI's `drift`, `label_cmd`, `resolve`, `verify_cmd`, `reset_drift` into `owner::act`; the CLI commands become thin wrappers (same output text — existing CLI tests unchanged).
- **Freshness check first, inside the write transaction:** drift → the session is still outside tolerance / red and not already answered since its last red; leftover → still open; verify → task still claimed/L1+ and not already L4 at HEAD; label → unit exists. Otherwise return `Err(Stale("already resolved: …"))` and append nothing.
- `NeedsYou.actions[i]` carries the exact `OwnerAction` JSON the screens send back, so no screen builds actions itself.

### Task 3: `bridge-screen ui` — server, token, lock, API, embedded SPA

**Command:** `bridge-screen ui [--port N] [--no-open]`:
```
lock = read ~/.bridge-screen/ui.lock
if lock and pid alive and GET 127.0.0.1:port/api/ping answers with the lock's token → print URL, exit 0
else (missing/stale) → bind 127.0.0.1:(--port or cfg.ui_port or 0), token = getrandom 32 bytes hex,
     write lock atomically (tmp + rename, 0600), print URL, open the browser unless --no-open
     (`open` on macOS, `xdg-open` on Linux, `cmd /c start` on Windows; failure is ignored)
on Ctrl-C / SIGTERM → remove the lock if it is still ours, exit 0
```
**API (axum Router, built by `ui::api::router(state)` so tests call it with `oneshot`):**
- `GET /api/ping` → `{ok, version}`; `GET /api/version` → `{last_event_pos}` (polling cursor, cheap: `SELECT max(pos)`)
- `GET /api/glance` → `Glance` (now = request time)
- `GET /api/project/{repo}`, `/api/session/{id}`, `/api/task/{repo}/{id}`, `/api/history/{repo}?kind=&session=&task=&before=&limit=` (≤ 200), `/api/tuning/{repo}` → Task 4 models
- `POST /api/action` (JSON `OwnerAction`) → `{reply}` or 409 `{error}` for stale, 400 for invalid
- every `/api/*`: token + Host checks (Global Constraints); JSON errors, never panics; request body ≤ 64 KB
- static: `rust-embed` (feature `interpolate-folder-path`) with `folder = "$BRIDGE_WEB_DIST"`. `build.rs` sets `cargo:rustc-env=BRIDGE_WEB_DIST=<abs path>`: `web/dist` when `web/dist/index.html` exists, else a folder it creates under `OUT_DIR` holding one placeholder `index.html` that explains how to build the dashboard. Same for the card (`BRIDGE_CARD_DIST`, `web/dist-card`). `cargo:rerun-if-changed` on both dist folders. The crate always compiles; crates.io source builds get the placeholder. Unknown non-API paths serve `index.html`.
- the router takes its assets through a small `AssetSource` trait (`get(path) -> Option<(bytes, mime)>`), implemented by the embed and by a test fake, so tests can serve "no build" without rebuilding
- the server uses a multi-thread tokio runtime; DB work runs in `spawn_blocking`

**Release/CI:** `release.yml` builds the web app before cargo-dist builds (use dist's `github-build-setup` hook, configured in `dist-workspace.toml`, running `npm ci && npm run build` in `web/`); `ci.yml` Rust jobs build the web first too, so the embedded assets are tested. Note in `docs/RELEASING.md`.

- [ ] Failing tests (`tests/ui_api.rs`, oneshot, temp home): `api_rejects_untrusted_requests`; glance/drill endpoints return the models; `POST /api/action` drift continue → `owner_action` recorded and the session's pending reply set; stale action → 409 and no event; history paging and filters; `ui_lock_single_instance_and_stale` (spawn the binary with a temp `HOME`, `--no-open`, `--port 0`; second start prints the same URL; kill -9 the first, third start replaces the lock); `ui_without_built_assets` (router with the placeholder `AssetSource`: `/` serves the build instructions, `/api/glance` still works; plus a `build.rs` unit-style check that the placeholder folder is chosen when `web/dist/index.html` is absent); the lock file is 0600 and contains no URL-fragment token in any log.

### Task 4: Drill-down models

`view::drill` (read-only, `now` passed in):
- **project(conn, repo, now)** → plan tree (id, kind, title, intent, status/level, stale badge, L4 owner mark, estimate vs actual minutes from `task_time`, deps), **scope line** (series of `{ts, total_live_estimate, done_estimate}` replayed from plan + verification events — one point per changing event, ≤ 500 points, downsampled evenly), re-plan history (`replan` events with reasons and op counts), decisions count per task.
- **session(conn, id, now)** → units timeline (no, start, stop, active min, label + source, drift score, detour label, files count), time split (on-task / per detour / drift minutes), suspended items with cues, checkpoints (sha, next action), leftovers from this session and their resolutions, latest handoff note, read-back result.
- **task(conn, repo, id)** → decisions with supersede chains (`decision::chain`), verification rows (level, by, rerun, sha, evidence, state), actors (distinct `actor.agent_type`/model from its units' events), retries (units after a `verification_failed`), `usage: None`.
- **history(conn, repo, filters)** → raw events newest first, data JSON truncated to 2 KB per row.
- **tuning(conn, repo, cfg)** → current thresholds vs defaults, each `config_changed` (old, new, samples, ts) with a revert action (`OwnerAction::ResetDrift`).
