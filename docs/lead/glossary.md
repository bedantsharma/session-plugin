# Glossary — bridge-screen

- **Owner:** you — the person the project serves and who decides. See: intent.
- **Session:** one Claude Code conversation working in one folder of a repo.
- **Sub-project (SP1–SP9):** the nine build stages in the design spec; each is a milestone in the plan.
- **Goal / milestone / task / subtask:** the plan tree, top to bottom. Progress is counted on the smallest pieces.
- **Unit (of work):** one round of an agent's work, from your prompt to the agent stopping. A unit **cut short** is one ended by your next message before the agent stopped; it is checked for drift from the files it touched.
- **Active time:** time an agent actually worked, minus time waiting on you or on permission prompts.
- **On task / detour / drift:** what a unit was. On task advances the task; a detour isn't the task but blocks it; drift does neither.
- **Asked for (code: `requested`):** a unit or detour that isn't the task but that you asked for in the session ("also add a licence"). Never counted as drift or time away; the agent declares it, and you can relabel any unit.
- **Tolerance band:** how much detour or drift time is normal before you're told (at least 15 min, or 20% of the task's estimate).
- **Resume cue:** a one-line note an agent leaves when it sets work aside, saying exactly where to pick up.
- **Needs you (queue):** things a session is blocked on until you act. The red count on every screen.
- **Done / idle (session):** a stopped session whose task is finished and nothing is pending / any other stopped session. Neither needs you.
- **Checkpoint (also called WIP commit):** a save-point commit an agent makes at task boundaries, marked `wip(bridge):`.
- **Squash:** merging all checkpoint commits into one before a pull request; a backup is kept.
- **Clean / dirty / crashed (session end):** ended tidily / ended with unsaved changes or unfinished work / went silent for 30 minutes.
- **Leftover:** an unsaved change a dead session left behind. You or an agent **adopt** it (commit it), **resume** it (keep working on it) or **undo** it (stash it away — recoverable).
- **Briefing:** the short status a new session gets when it starts. **Read-back:** the agent repeating it back so mistakes surface early. **Handoff note:** what a stopping agent leaves for the next one.
- **Verification ladder (L0–L4):** L0 claimed done · L1 the code exists · L2 tests pass · L3 checked end to end · L4 you signed it off. **Stale:** a later change touched the verified files, so it dropped a level.
- **Done% / claimed%:** share of estimated work verified at L2 or above / claimed but not yet verified.
- **Exploring / executing (also called uphill / downhill, from hill charts):** a milestone with unknowns left (its % may change) / one where the path is clear (its % is reliable).
- **Stuck:** a milestone whose progress hasn't moved over three sessions that worked on it.
- **Take back sign-off (withdraw):** undoing your last verdict on a task — a sign-off, or a "broken" — so it goes back to where it was before. Only you can do it (`bridge-screen verify <task> --withdraw` or the button on the task page).
- **Roll-up (milestone / goal status):** a milestone or the goal reads done, in progress, needs attention or to do, worked out from its tasks every time you look.
- **Owner action:** anything you do from a screen or the CLI (answer a drift, sign off, resolve a leftover); recorded like everything else.
- **Tokens:** the units of text a model reads and writes; what usage is billed in. Cached reads are cheap, cache writes cost a little more than plain input.
- **Cost (per task, session, project):** tokens times the prices in your config, worked out when you look (never stored); "unknown" when a model has no price.
- **Forecast (P50 / P90):** the finish range. P50 = a 50% chance of being done by that date ("likely by"); P90 = a 90% chance ("could take until").
- **Calibration:** how long finished tasks actually took against their estimates (e.g. "tasks typically take 1.8× their estimate" — the middle value, so one runaway task doesn't skew it); the forecast is built from it.
- **Imported plan:** a plan file in `docs/superpowers/plans/` that bridge-screen read into the plan by itself (it never writes to the file). A ticked step counts as claimed done, never checked. A file already planned by hand is only noted, not imported.
- **Set up (`bridge-screen init`):** for a repo with work but no plan: bridge-screen lists what the repo shows, the agent drafts a plan, you confirm it once, and tasks that look done are recorded as claimed and checked for "the code exists".
- **Waiting on (a wait):** a session saying it is blocked on a task (here or in another repo) or on something outside ("Sam's API key"). Shown as an amber "waiting"; a wait on a task ends by itself when that task's tests pass. Not a needs-you item.
- **Plan link (dependency):** a task that can't finish before another task, possibly in another repo (`api:2.4`). A wait can be turned into one ("Make it a plan link").
- **Branch group:** the same branch with live sessions in two or more repos, shown as one line with a combined done%.
- **Glance / drill-down:** the first dashboard screen / the detail pages behind it.
- **Desktop card:** the inline progress view inside the Claude desktop app.
- **Hook:** the moment Claude Code hands an event to bridge-screen. **MCP tools (agent tools):** the functions agents call on bridge-screen. **Skill:** the instructions that teach agents the protocol.
- **Worktree:** a second working folder of the same repo, so parallel sessions don't trip over each other.
- **Living docs:** these five pages in `docs/lead/`: intent, project map, current state, decision log, glossary. For any other repo bridge-screen offers the same five as *project pages*.
- **Project pages:** the same five pages (what the project is for, how it fits together, where things stand, why choices were made, the words used) for any repo bridge-screen is used in. Kept in bridge-screen's own folder (`~/.bridge-screen/lead/`), never in the repo, and shared by every worktree. Created only after you say yes once (`bridge-screen pages set-up`); agents read and update them; the dashboard shows them read-only. See: project map, Project pages.
